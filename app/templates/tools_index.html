Network tools

Five diagnostic tools that run on our server using Python libraries only. No shell commands are ever executed, and private or internal addresses are refused.

Rate limit: {{ rate_limit_max }} requests per {{ rate_limit_window }} seconds per IP address, shared across all five tools. Requests that look like attempts to reach private networks are rejected outright.

DNS lookup

Resolve a hostname and see the A, AAAA, MX, NS, TXT, CNAME, SOA or CAA records, with the TTL and query time.

Public IP info

See the public IP address this server appears to come from, with approximate country, city and network operator.

Port checker

Test whether a common TCP port is open, closed or filtered. Restricted to a fixed list of well-known ports.

HTTP status check

Check that a website responds, with the status code, server header, content type and response time.

Latency test

Measure TCP connect latency to a host over several attempts, with minimum, average, median and jitter. Uses TCP rather than ICMP, so it needs no special privileges.

How these tools protect you

  • • No shell is ever invoked. Everything uses Python libraries, so there is no command injection surface.
  • • Hostnames are resolved and every returned address is checked. Private, loopback, link-local and reserved ranges are refused, which blocks SSRF attempts against internal services.
  • • Requests connect to the already-validated IP address, so a DNS change cannot redirect them to an internal target afterwards.
  • • Only HTTPS is allowed for web requests, redirects are not followed, and response bodies are capped.
  • • All timeouts are short and bounded, so a slow target cannot tie up the server.
